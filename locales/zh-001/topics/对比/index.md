本页根据典型特征，将本项目与其他三**类**系统进行比较。具体产品的页面列在下方。详情应向供应商确认。

> 主要区别在于成熟度：其他方案已在实际使用，而本项目没有。它尚不能用于真实患者。

## 摘要

| | 本项目 | 大型商业系统 | 纯提醒服务 | 电子表格和电话 |
|---|---|---|---|---|
| **用于真实患者** | 尚未 | 是 | 是 | 是 |
| **安全保障** | 尚未完成 | 通常具备 | 通常具备 | 取决于当地做法 |
| **支持合同** | 暂无 | 有 | 有 | 无 |
| **软件许可费** | 无 | 通常有 | 通常有 | 无或很低 |
| **可以阅读和修改代码** | 是 | 通常不行 | 通常不行 | 不适用 |
| **提醒可升级到真人** | 是 | 因产品而异 | 因产品而异 | 人工操作 |
| **患者回复可更改预约** | 是 | 因产品而异 | 因产品而异 | 人工操作 |
| **内置公平性衡量** | 是 | 因产品而异 | 很少 | 人工操作 |
| **保存临床记录** | 否，这是设计决定 | 经常 | 否 | 否 |
| **候诊名单和 RTT 计时** | 是 | 是 | 否 | 人工操作 |

## 适用情况

### 大型商业系统

适用于需要经过验证、有技术支持、包含临床记录且有责任供应商的系统的情况。

### 纯提醒服务

可以较低成本在现有系统上增加提醒，但通常不会改变候诊名单或员工任务流程。

### 电子表格和电话

适用于小型服务，但扩展性差，也难以衡量就医情况。

### 本项目

适合希望审查代码、影响设计、研究就医公平性或参与贡献的机构。它不适合实际使用。

## 范围之外

- 它不是临床记录。它不保存诊断、处方或生命体征。
- 它不会自动对患者做出任何决定。
- 它不会超额预约，任何评分都不能夺走任何人的号源。
- 它不保存身份信息，需要与 `person-service` 和 `worker-service` 配合使用。
